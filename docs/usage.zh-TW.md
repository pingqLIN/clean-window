# 操作與還原

[專案首頁](../README.zh-TW.md) · [English](usage.md)

只處理你指定的 Chrome 視窗或分頁，不更動 Chrome 全域外觀設定。

**狀態：94 項自動化測試通過；Chrome Dev Headless DOM 已測試三模式介面、跨來源授權流程與 YouTube 版面；尚未完成完整 MV3 Chrome GUI／使用者 Windows 實機驗收。**
本次雲端測試環境限制擴充載入與全螢幕，未修改或繞過其政策。

## 三級精簡操作

設定滑桿：1 為常駐顯示的 86px 自繪雙列工具列，包含網址導覽與擴充快捷入口；啟動後立即完整展開、不收闔。一般網頁預留工具列高度；AI 對話工作區不改動其根布局。2 只保留 48px 自繪網址欄，預設收闔在頂部中央的 76×6px 把手後方；滑鼠移入或鍵盤聚焦即可展開，不含擴充快捷工具列，也不預留頁面空間。3 是純精簡 Popup，不顯示頁面頂部的自繪網址欄或工具列。三種皆只搬移目前分頁，保留可拖曳縮放的視窗標題列。預設第 1 級。

第 1 級提供書籤星號、最近書籤、乾淨視窗清單、歷史紀錄、下載、擴充管理及還原。這些是 Clean Window 自繪快捷入口，不是 Chrome 原生工具列，不能代替第三方擴充按鈕。書籤功能按需另行授權。自繪網址欄不提供可信任網站來源／安全標誌；第 1、2 級需要在可注入的 HTTP(S) 頁面才能顯示，注入失敗會阻止切換。第 3 級不顯示頁面頂部工具列或網址欄，因此即使受限頁面無法注入，也仍可開啟純精簡 Popup。第 1、2 級透過自繪網址欄跨來源導覽時會先提供單站授權選擇；若使用網站連結或重新導向跨來源，且尚未授權該網域，介面可能消失，可透過右鍵選單重新啟用。頁面邊緣的三級控制標籤與標題處理功能是獨立於頂部工具列的功能。

**主題快速切換：** 第 1 級常駐網址欄右方可點 `☾`／`☀`；第 2 級需先展開隱藏式網址欄才可切換明暗介面。第 3 級沒有頂部網址欄，因此沒有這項控制。偏好存於本機，並不更動 Chrome 原生 UI 或網頁。網址欄不再顯示「Clean Window · 自繪」字樣。

**乾淨視窗清單：**在一般 Chrome 視窗開啟 Clean Window 擴充 Popup，展開「已啟用乾淨視窗」；第一級工具列也有相同入口。清單逐筆顯示 Emoji/標題及等級，可聚焦、切換 L1/L2/L3 或還原。清單只辨識實際受管理、仍開啟的 Popup，不會誤抓其他分頁。

**書籤授權：**在第一級點「☆」或「▤」，未授權時先開啟擴充自己的授權小視窗；**必須在該小視窗再次按「允許使用 Chrome 書籤」**，才會跳出 Chrome 權限確認。授權後返回第一級工具列使用星號與最近書籤。拒絕授權不影響其他功能；可於 Chrome 的擴充管理頁管理此權限。

**頁面邊緣控制：** 左右邊緣的 `◈` 標籤預設不顯示文字；滑鼠移入或鍵盤聚焦後展開上中下三級，僅在檔位 Hover／聚焦時浮現說明。點選會直接切換目前 Popup 內的自繪欄位，不重新移動分頁；可拖曳標籤吸附左右兩側並調整高度，位置存在本機。特殊頁面或跨來源導覽可能導致注入失效，屆時用還原快捷鍵。

Alt + Shift + R 可還原；Alt + Shift + F 仍是獨立的全螢幕快捷鍵，不在三級滑桿中。

**標題快速入口：** 在已啟用乾淨模式、可注入的一般網頁上，單擊側邊中性灰無字標籤即可開啟標題編輯器；拖曳則移動邊緣工具。編輯器支援一個 Unicode Emoji 字素（含國旗、組合表情及膚色）、常用 Emoji 按鈕與既有 Symbol。Chrome 原生標題列的點擊無法由擴充接管。

**標題：** 乾淨 Popup 的頁面標題預設是 `◈ 原始網頁標題`；`Alt + Shift + T` 或在頁面按右鍵選「Clean Window · 編輯乾淨模式標題」可開啟 Symbol＋文字編輯器。可選擇標準 Unicode Symbol、編輯文字、取消或重設為原始標題。離開乾淨模式時恢復最近的網頁原始標題。只有可注入的 HTTP(S) 網頁支援編輯，SPA 網站自行更新標題時會追蹤更新；不變更真正的 favicon、Chrome 安全圖示或其他分頁。

## 側邊模式列預覽

滑鼠停留在實際側邊模式列的某一檔約 150ms，或用鍵盤聚焦該檔，即可暫時預覽。虛線標示預覽目標，原本的已選取模式不變。只有點擊該檔（或鍵盤啟動按鈕）才正式套用並儲存；移出整個側邊模式列、焦點離開或按 Esc，會還原原模式及進入預覽前的捲動位置。Popup 面板裡的示意側標不會預覽目前網頁。

播放器會以約 200ms 的位移及縮放過渡到新位置；恢復的頁面內容淡入，網址欄沿用淡入淡出效果。使用同一個影片元素，不複製播放器或擷取舊影格。系統設定「減少動態效果」時直接切換，不播放過渡動畫。快速移動會取消舊預覽，只保留最新目標。

拖曳側標、調整視窗、開始頁面導覽、進出影片全螢幕或視窗失去焦點會取消暫時預覽。預覽不搬移分頁、不調整外框、不儲存模式；套用失敗會恢復原模式。更新擴充後需重新啟用既有乾淨視窗，才會載入新的預覽腳本。

## YouTube 播放頁

在桌面版 YouTube `/watch` 播放頁啟用乾淨視窗後，使用原有三級控制切換：

| 模式 | YouTube 行為 |
| --- | --- |
| 1 | 保留 YouTube 原生版面，並將內容移至常駐雙列工具列下方。 |
| 2 | 網址欄收闔時不預留空間；展開後移除網站頁首及原本播放器高度限制，依影片比例與可視高度安排播放器，保留標題、留言、推薦內容與配色。 |
| 3 | 不顯示頁面頂部工具列或網址欄；播放器固定填滿網頁內容區，隱藏播放器之外的網站內容，只保留影片、播放控制及擴充邊緣控制；使用黑色背景並收起捲動條。 |

影片一律保持原比例，完整顯示、不裁切。拖曳外框時，播放器跟隨內容區大小；此功能不會自動改變外框尺寸。要四邊貼齊，將第 3 級的內容區調成影片比例（一般影片為 16:9）；第 2 級只有在網址欄展開時才扣除其實際高度。原生視窗標題列與邊框仍保留。

尺寸依目前可視區域及工具列實際高度計算，統一使用 CSS 像素，不沿用某台螢幕的解析度或固定扣除 48px。視窗／工具列尺寸改變會更新版面；支援時使用動態視窗高度單位，舊版回退為 `vh`。瀏覽器縮放與顯示縮放不需自行換算實體像素。測試涵蓋多組模擬視窗尺寸及像素比例；實體多螢幕與 DPI 切換仍需人工驗收。

同一分頁內切換影片會繼續套用；前往搜尋或首頁會移除效果，回到播放頁會恢復。原生影片全螢幕期間暫停專用樣式，退出後恢復。切回第 1 級時恢復原生 YouTube 版面並把內容移至常駐工具列下方；離開乾淨模式則移除全部專用樣式與偵測器。不支援 Shorts、嵌入頁、YouTube Music 或非 YouTube 網站；手機版頁面若沒有桌面播放器結構也不套用。完整重新載入後仍受 Chrome 原有注入權限限制。

更新原始碼後，先還原既有乾淨視窗，在 `chrome://extensions/` 重新載入擴充，再於目標分頁啟用。先前以 DevTools 注入的臨時示範樣式需重新整理該頁移除，避免與正式模式重疊。

## 安裝（不需要 Node、Python、伺服器或管理員權限）

1. 若使用原始碼 ZIP，解壓縮到固定資料夾；若使用 Runtime ZIP，解壓後的根目錄就應直接看得到 `manifest.json`。請保留選定的資料夾，不要移動或刪除。
2. 在 Chrome 開啟 `chrome://extensions/`，開啟「開發人員模式」。
3. 按「載入未封裝項目」，選擇**直接包含 `manifest.json` 的資料夾**：原始碼 ZIP 選 `clean-window\extension`；本機建置選 `dist/runtime/`；Runtime ZIP 則選解壓後的根目錄。不要選 ZIP 檔本身，也不要選上層專案根目錄。
4. 在右上角擴充功能選單，把「Clean Window｜乾淨視窗」釘選。切到要處理的視窗，點圖示選擇模式。

安裝完成後請保留 extension 資料夾，不要移動／刪除。企業管理的 Chrome 可能不允許開發人員模式或未封裝擴充；本套件不繞過管理政策。

## 操作與還原

| 操作 | 預設快捷鍵 |
| --- | --- |
| 依照滑桿等級套用簡化模式／還原 | `Alt + Shift + W` |
| 整個目標視窗切換全螢幕 | `Alt + Shift + F` |
| 還原目前視窗 | `Alt + Shift + R` |
| 編輯乾淨模式的 Symbol＋標題 | `Alt + Shift + T` |

精簡後沒有 Chrome 原生工具列，**先記住 `Alt + Shift + R`**。也能在一般網頁空白處按右鍵，選 `Clean Window · 還原目前視窗`。網站禁止右鍵、自訂選單或 Chrome 內部頁面可能使右鍵入口無法使用，這時使用快捷鍵。

快捷鍵沒有反應時，開啟 `chrome://extensions/shortcuts` 指定未占用的組合。Chrome／作業系統與其他擴充可能占用快捷鍵，Windows 的 Alt+Shift 語言切換設定也可能衝突。面板會顯示實際註冊的組合；未註冊時顯示「未指定快捷鍵」。

從精簡視窗還原：原視窗仍存在時嘗試放回原視窗與原分頁位置；不存在時建立新的普通視窗，不擅自塞進其他 Chrome 視窗。Chrome 重啟／重新載入擴充可能清除原視窗對應，這時仍可把精簡視窗還原為新的普通視窗。

按系統的「X」是正常關閉該分頁，**不是還原**。請用還原入口。

## 跨來源導覽與重新啟用

- **同來源導覽：**例如同一網站從 `/watch` 切換到另一個影片頁，不會額外詢問網站存取權。
- **從自繪網址欄前往其他來源：**Clean Window 會開啟一個小型的網站存取選擇視窗。按「允許此網站並繼續」後，Chrome 會要求授權目標網域。HTTPS 目標只請求 HTTPS；若輸入 HTTP，則同時請求同一網域的 HTTP 與 HTTPS，以支援常見的自動升級跳轉。授權後，該網域的頁面可在後續導覽中重新掛載精簡介面。這是選用權限，不會在安裝時授予所有網站。Chrome 的 host permission 不會分別限制 URL 路徑或 port。
- **不授權：**按「不授權，仍然前往」可繼續開啟目標網站，但工具列可能消失；按「取消」則留在目前頁面。
- **由網站連結、登入跳轉或重新導向跨來源：**如果目標網域尚未授權，Chrome 會撤銷原本的 `activeTab` 存取，介面可能消失。於頁面按右鍵，選 `Clean Window · 重新啟用目前網站的精簡介面`，即可對目前網站按需重新注入，使用的是暫時性 `activeTab` 權限，不會建立永久網站授權。也可以按 `Alt + Shift + R` 先還原，再重新啟用乾淨模式。
- **Chrome 限制頁面：**`chrome://`、Chrome 線上應用程式商店及其他受限制頁面不支援一般頁面注入，應使用普通視窗或還原功能。

## 不影響其他視窗的設計

所有操作都綁定觸發當下的 `windowId`、`tabId`。分頁已移走或關閉時回報錯誤，不改操作另一個當下取得焦點的視窗。只更新目標視窗；不改全域書籤列偏好、不改 Profile、不重啟 Chrome、不批次關閉視窗。

切換時焦點自然會移到目標或還原視窗；「不影響其他視窗」指不更動其外觀設定、大小、模式與分頁內容，不代表焦點完全不會改變。

## 使用前知道的限制

- 精簡模式只移動一個目前分頁，不是把同一視窗全部分頁收進一個無分頁列視窗。
- 此版不把群組或 Split View 分頁移出，避免破壞結構；可改用全螢幕模式。
- 搬走原視窗最後一個分頁時，Chrome 會自然關閉空視窗。還原時可能是新的 windowId；依賴原 windowId 的其他自動化應使用全螢幕模式。
- 程式使用既有 tabId，不依 URL 重新開頁，不主動 reload；但是視窗大小改變可能觸發網站自己的 resize 邏輯，未儲存資料仍須先保存。此點尚未經本機實際網站驗收。
- 第 1–3 級保留系統標題列／關閉按鈕並可縮放；獨立全螢幕快捷鍵可另行切換視窗狀態。不使用已棄用的 Chrome Apps API。
- Chrome 自身安全提示、下載／權限提示不會被移除。特殊 Chrome 頁面、已安裝 PWA、Isolated Web App 或其他擴充頁面的移動可能受 Chrome 限制；遇到 API 拒絕會回報錯誤。
- 要在無痕模式使用，需自行於擴充詳細資料允許無痕；程式採 split 模式並保留目標的 incognito 屬性，不跨一般／無痕視窗還原。

## 建議的首次驗收

先用一般測試頁面，不要直接拿尚未儲存的重要表單測試。

1. 開兩個 Chrome 視窗 A、B，讓 A 有兩個分頁，B 保持一般模式。
2. 測試第 1 級，確認雙列工具列、書籤授權及乾淨視窗清單可用；還原後測第 2 級，確認仍有網址欄但沒有擴充欄。
3. 測試第 3 級，確認沒有任何自繪工具列。使用 `Alt+Shift+T` 編輯 Symbol 與文字，確認標題會更改；再按 `Alt+Shift+R` 還原並確認原網頁標題恢復。全螢幕另由 `Alt+Shift+F` 測試。
4. 若 A 使用群組／Split View，改以全螢幕測試；若快捷鍵未註冊，先在 shortcuts 頁面設定。

## 權限與資料

必要權限為 `storage`、`contextMenus`、`activeTab` 與 `scripting`；`bookmarks` 與 HTTP(S) host access 為選用權限。選用 host patterns 只在使用者主動透過自繪網址欄跨來源導覽時，才對目標網域提供授權選擇；HTTPS 目標只請求 HTTPS，HTTP 目標則同時請求同一網域的 HTTP 與 HTTPS，以支援常見自動升級；安裝時不會授予所有網站。所選等級與標籤位置存於 `chrome.storage.local`，還原資訊維持 `chrome.storage.session`；沒有常駐 content script、必要的全站 host permission、`tabs` 敏感資料權限、網路請求、遙測或 Native Messaging。網站授權視窗開啟期間，待導覽網址會暫存在 `chrome.storage.session`，導覽、取消、相關視窗關閉後移除；若逾時，會在下次存取該請求時清除。不寫入 `storage.local` 或同步資料。標題自訂只存在目前頁面的執行記憶體，不上傳、不存入持久儲存。

## 開發與測試

安裝擴充不需執行下列指令。只有修改程式時需要 Node.js 20+；沒有 npm 依賴，不需要 `npm install`。

```sh
npm test
npm run check
```

`tests/browser-smoke.py` 是開發用實機測試腳本，不是擴充執行的一部分，需 Playwright、Pillow 與可載入擴充的 Chromium。Linux 須另有 Xvfb、Openbox；腳本使用暫存 Profile、僅 loopback 測試頁，遇到已知管理政策限制就以 BLOCKED 停止，不修改政策。

完整結果見[驗證紀錄](verification.md)。本機測試輸出位於被 Git 忽略的 `evidence/`，不納入公開原始碼。
