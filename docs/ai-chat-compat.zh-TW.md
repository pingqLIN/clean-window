# AI 對話網站相容性（2026-10-22）

## 問題
在 Clean Window 第一／二級精簡視窗中，Gemini、Claude、ChatGPT 的側邊欄／底部功能可能不完整；ChatGPT 有時會重新排版，但仍須捲動才可看到底部控制。

## 原因與修正
- **程式碼確認**：原工具列在 `document.documentElement` 加入 48px 或 86px 的 `padding-top !important`。這可能讓採用 `100vh`、固定高度或獨立捲動容器的 SPA 導覽側欄出現超出視窗範圍的內容。
- **相容模式**：在下列精確 host 啟用「不改動 HTML 根節點」模式：`gemini.google.com`、`claude.ai`、`www.claude.ai`、`chatgpt.com`、`www.chatgpt.com`、`chat.openai.com`。
- 第一／二級原本的自繪網址欄與第一級擴充工具列保留功能，但以頂部中央可聚焦／滑鼠展開的小型收合控制呈現；收合時不覆蓋原站左／右上角的操作。
- 第三級新增預設隱藏的自繪網址欄（上緣中央 Hover／鍵盤聚焦展開），不顯示擴充工具列；YouTube 專屬影片模式維持播放器填滿內容區的行為。
- 不新增任何網站存取權限，也不隱藏、刪除或改寫 AI 網站原生元件。

## 驗證
- `npm test`：控制器與擴充現有單元測試。
- `npm run check`：MV3／語法／套件檢查。
- `npm run smoke:dom`：在隔離 Chrome Headless 模擬 100vh 側欄、底部送出按鈕，檢查第一／二級不影響根節點高度，收合控制可操作、非目標 host 不受影響，及不同視窗高度。
- **尚未驗證**：登入狀態 Gemini、Claude、ChatGPT 實際線上版本的側欄展開／收合、對話清單、底部帳戶選單、輸入／附檔與捲動操作，需在載入此分支後實測。

## 實機驗收重點
1. 依序開啟三站，在原站先確認側邊欄、輸入與底部選單存在。
2. 啟動第一級，確認底部選單仍可見；移動到視窗頂部中央展開工具列，再移開。
3. 切至第二級，確認網站功能完整且網址欄可展開。
4. 切至第三級或還原普通視窗，確認所有原生功能未受殘留樣式影響。
5. 分別以較窄、較短與最大化視窗重測；記錄仍缺失的功能名稱和截圖。
